## 八、自动化单元测试（P2 新增 · 2026-09-15）

> 在原有手工接口测试（Postman/Apifox，见上）基础上，P2 阶段补充了 JUnit5 + Mockito 自动化单元测试，作为回归防护网，与手工测试互补。

### 8.1 测试类与用例

| 测试类 | 模块 | 被测对象 | 用例数 | 覆盖点 |
|--------|------|---------|-------|--------|
| `MedicalPatientServiceImplTest` | ruoyi-system | `MedicalPatientServiceImpl` | 5 | 按 ID 查 / 列表查 / 新增 / 修改 / 批量删除 的 Mapper 委托与返回值透传 |
| `MedicalDrugServiceImplTest` | ruoyi-system | `MedicalDrugServiceImpl` | 5 | 同上（药品实体） |
| `MedicalDiagnosisServiceImplTest` | ruoyi-system | `MedicalDiagnosisServiceImpl` | 5 | 同上（诊疗实体） |
| `DrugControllerTest` | ruoyi-admin | `DrugController` | 6 | 列表分页封装、详情成功返回、新增/修改/删除的 `toAjax` 边界（行数>0 成功、=0 失败） |

合计 **21 个自动化测试用例**。

### 8.2 技术要点

- 采用 Mockito 隔离，**不启动 Spring 容器 / 不连 MySQL / 不连 Redis**，本地只要有 JDK + Maven 即可运行。
- Service 测试用 `@ExtendWith(MockitoExtension)` + `@InjectMocks`；Controller 测试用 `new` 实例化后 `ReflectionTestUtils.setField` 注入 Mock 的 Service。
- 依赖已加入 `ruoyi-system`、`ruoyi-admin` 的 `pom.xml`（`spring-boot-starter-test`，`scope=test`，不进生产包）。

### 8.3 运行命令

```bash
mvn test                       # 全部模块
mvn -pl ruoyi-system test      # 仅业务层
mvn -pl ruoyi-admin test       # 仅控制层
mvn -pl ruoyi-system test -Dtest=MedicalDrugServiceImplTest  # 指定类
```

### 8.4 沙箱限制（重要）

当前自动化构建环境**未安装 JDK**，上述单元测试**无法在本环境执行**，仅做了代码级正确性核验（方法签名、Mockito 用法、若依 `TableDataInfo` / `AjaxResult` / `TableSupport` API 匹配）。请在本地 JDK + Maven 环境执行 `mvn test` 验证全绿（预期 21/21 通过）。

## 14. 并发压测：验证原子 SQL 不超卖（2026-09-17 实跑）

### 14.1 目的

挂号占用号源、发药扣减库存是本系统**唯一两处会被并发击穿的地方**。
代码层面用的是「条件更新」而非「先查后写」：

```sql
UPDATE medical_schedule SET used_num = used_num + 1
 WHERE schedule_id = ? AND used_num < total_num;     -- 号源：影响行数 0 即号满

UPDATE medical_drug SET stock = stock - ?
 WHERE drug_id = ? AND stock >= ?;                    -- 库存：影响行数 0 即库存不足
```

本节用真实并发（多线程直连 MySQL）验证这两条 SQL 是否真的挡得住超卖，并设**对照组**证明不加守卫会出问题。

### 14.2 实验设计

脚本：`.workbuddy/concurrency_test.py`（连接信息从 `application.yml` 读取，不硬编码密码；
实验数据用 `__CONC_TEST__` 标记的临时行，跑完自动清理）。

| 组 | SQL 写法 | 资源上限 | 并发数 |
|---|---|---|---|
| A | 原子号源占用（带 `used_num < total_num` 守卫） | 剩余名额 5 | 20 / 50 |
| B | 原子库存扣减（带 `stock >= qty` 守卫） | 库存 10 | 20 / 50 |
| C | **对照组**：先 `SELECT` 读库存再 `UPDATE` 写回（无守卫） | 库存 10 | 20 / 50 |

### 14.3 实测结果

**并发数 = 20**

| 实验 | 成功次数 | 应为 | 最终状态 | 耗时 | 结论 |
|---|---|---|---|---|---|
| A 原子号源占用 | 5 | 5 | used_num = 5/5 | 2069 ms | 通过 |
| B 原子库存扣减 | 10 | 10 | stock = 0 | 1939 ms | 通过 |
| C 对照组（先读后写） | 20 | 10 | **stock = 9** | 994 ms | 出现超卖（预期内） |

**并发数 = 50**

| 实验 | 成功次数 | 应为 | 最终状态 | 耗时 | 结论 |
|---|---|---|---|---|---|
| A 原子号源占用 | 5 | 5 | used_num = 5/5 | 2493 ms | 通过 |
| B 原子库存扣减 | 10 | 10 | stock = 0 | 2409 ms | 通过 |
| C 对照组（先读后写） | 50 | 10 | **stock = 9** | 2051 ms | 出现超卖（预期内） |

### 14.4 结论与答辩用法

1. **A/B 两组**：无论 20 还是 50 并发，成功次数**恰好等于资源上限**（5 / 10），
   最终 `used_num` 不超过 `total_num`、`stock` 不降到负数 ——
   **原子条件更新生效，不超卖**。
2. **C 组（对照组）**：50 个并发请求**全部返回成功**，但实际库存只从 10 降到 9（只扣了 1 件）。
   这是典型的**丢失更新（lost update）**——前端拿到 50 次"成功"，账实严重不符。
3. 这组对照是答辩最有力的证据：**不是"我用了事务所以安全"，而是实测证明
   去掉 WHERE 守卫就会超卖、加上就不会**。建议把这个表直接放进论文"系统测试"章节。


### 14.6 纠错：响应拦截器返回的是完整响应体（此前记录有误）

本文档 13.2 第 3 点写「RuoYi 响应拦截器已解包 `res.data`，前端再取 `.data` 会变 `undefined`」，
**该描述不准确**，按 `ruoyi-ui/src/utils/request.js` 实际代码纠正如下：

- 拦截器 `return res.data`，即**HTTP 响应体本身**（axios 的 `res.data`），
  而不是若依 `AjaxResult` 里的 `data` 字段。
- 因此业务页拿到的 `res` 就是后端返回的 JSON 顶层对象：
  - 列表接口返回 `TableDataInfo` → 直接用 `res.rows` / `res.total`（正确写法）；
  - 普通接口返回 `AjaxResult.success(x)` → 需取 **`res.data`** 才是业务数据 `x`。
- 后者若误写成"不能再取 `.data`"，会导致 `AjaxResult.success(diagnosisId)`
  这类接口的返回值取不到（例如挂号「开始就诊」返回的诊疗ID）。

**修法一句话**：看后端返回的是 `TableDataInfo` 还是 `AjaxResult`——
前者用 `res.rows`，后者用 `res.data`。

### 15.3 发现并修复的缺陷：检索无相似度阈值（重要）

- **现象**：最初三组里"电脑蓝屏"竟 `hit=true`，references 还硬塞了"发热伴胸痛/手足口/血脂"三篇毫不相干的内容，模型据此编出"建议前往医院就诊"。
- **根因**：`rag.py` 原 `retrieve()` 用 `hit = len(documents) > 0` —— 只要 Chroma 返回 top_k 就当命中，**无任何相似度阈值**，跨主题问题也被当成命中交给大模型。
- **修复**（三处）：
  1. `scripts/build_rag_db.py` 建集合改 `metadata={"hnsw:space": "cosine"}`；
  2. `config.py` 新增 `RAG_SIM_THRESHOLD = 0.55`；
  3. `rag.py` 的 `retrieve()` 增加阈值过滤，过滤后为空则 `hit=false`，上层据此触发**拒答分支**。
- **修复后**：库外问题正确拒答，库内两组问答不受影响。这是医学场景防幻觉的关键设计，答辩被问"知识库没有的问题怎么处理"可直接演示。
