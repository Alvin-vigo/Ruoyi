# 若依医疗管理系统部署说明

## 一、部署环境要求

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| JDK | 1.8+ | 推荐使用 JDK 1.8 或 JDK 11 |
| Maven | 3.6+ | 用于后端项目构建 |
| MySQL | 8.0+ | 数据库服务 |
| Node.js | 14.x / 16.x | 用于前端项目运行 |
| npm | 6.x+ | Node.js 包管理器 |

## 二、后端部署步骤

### 2.1 导入数据库

1. 登录 MySQL，创建数据库（或直接执行脚本中的建库语句）：

```bash
mysql -u root -p
```

2. 执行项目根目录下的数据库脚本（**顺序不能错**）：

```bash
# 先建库并选中（只需一次）
CREATE DATABASE ry-vue CHARACTER SET utf8mb4;
USE ry-vue;

source /path/to/若依医疗/sql/ry_20231130.sql        # 若依基础表(sys_user/sys_menu/sys_role...)【必须先】
source /path/to/若依医疗/sql/medical_schema.sql     # 患者/诊疗/药品业务表 + 代码生成器表 + 测试数据
source /path/to/若依医疗/sql/medical_followup.sql   # 患者随访表 medical_followup + 示例数据【新增，必选】
source /path/to/若依医疗/sql/medical_message.sql    # 站内信表 medical_message【新增，必选】
source /path/to/若依医疗/sql/quartz.sql             # 定时任务表(QRTZ_*) + sys_job/sys_job_log【必选，ruoyi-quartz 模块已启用】
source /path/to/若依医疗/sql/medical_menu.sql        # 医疗菜单/权限(依赖上面的 sys_menu)，含费用报表/随访/站内信/监控管理菜单
source /path/to/若依医疗/sql/medical_ai.sql          # AI 模块 4 表(medical_ai_record / medical_risk_predict / medical_chest_xray / medical_rag_knowledge)
source /path/to/若依医疗/sql/medical_ai_menu.sql     # AI 模块菜单/权限
source /path/to/若依医疗/sql/medical_drug_menu.sql   # 药品菜单(若与 medical_menu 冲突请核对 menu_id)
```

> 说明：`ry_20231130.sql` 建若依基础表（含 `sys_menu`），`medical_menu.sql` 往 `sys_menu` 插菜单，**必须在其之后执行**；`medical_schema.sql` 已包含全部业务表（患者/诊疗/药品）、代码生成器表及测试数据，一次性建表并初始化；`medical_followup.sql` 为本次新增的随访模块建表脚本（含 2 条示例数据），**需单独执行**；`quartz.sql` 在原有 11 张 `QRTZ_*` 表基础上**新增 `sys_job` / `sys_job_log` 两张业务表**，因 `ruoyi-quartz` 模块已并入主工程，定时任务功能不再可选，必须导入。

> 菜单说明：`medical_menu.sql` 已在「医疗管理」目录下追加 **费用明细报表**（component=`medical/feeReport/index`）、**患者随访**（component=`medical/followup/index`）、**站内信**（component=`medical/message/index`）三个二级菜单，并在根部新增 **监控管理** 一级目录，其下含 **定时任务**（component=`monitor/job/index`）、**定时任务日志**（component=`monitor/job/log`）。配套权限码：`medical:fee:*`、`medical:followup:*`、`medical:message:*`、`monitor:job:*`。

> 定时任务自动加载：`quartz.sql` 末尾已以幂等方式种入两条 `sys_job` 记录（随访逾期提醒 `followupRemindTask.scanOverdueFollowup`、低库存预警 `medicalRemindTask.scanLowStock('10')`）。应用启动时 `SysJobServiceImpl.init()`（`@PostConstruct`）会从 `sys_job` 全量加载并注册到调度器，**无需手动在前端新增**。任务执行后通过 `SpringUtils` 取业务服务，将提醒写入站内信。注意：`ScheduleUtils.createScheduleJob` 已加幂等保护（已存在则先删再注册），确保 JDBC 持久化存储下重启不会因任务已存在而启动失败。

3. 修改后端数据库连接配置：

编辑 `ruoyi-admin/src/main/resources/application.yml`：

```yaml
spring:
  datasource:
    druid:
      url: jdbc:mysql://localhost:3306/ry-vue?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
      username: root
      password: your_password
```

### 2.2 编译后端项目

在项目根目录执行：

```bash
mvn clean install -DskipTests
```

编译成功后，进入启动模块运行：

```bash
cd ruoyi-admin
mvn spring-boot:run
```

或者直接运行启动类：

```bash
com.ruoyi.RuoYiMedicalApplication
```

### 2.3 后端接口验证

启动成功后，可通过以下地址验证：

- 患者列表接口：`http://localhost:8080/medical/patient/list`
- 诊疗列表接口：`http://localhost:8080/medical/diagnosis/list`
- 药品列表接口：`http://localhost:8080/medical/drug/list`
- 药品低库存预警接口：`http://localhost:8080/medical/drug/low-stock?threshold=10`
- 医疗数据看板接口：`http://localhost:8080/medical/statistics/dashboard`
- 代码生成器接口：`http://localhost:8080/tool/gen/list`

## 三、前端部署步骤（RuoYi-Vue）

本项目在 `ruoyi-ui` 目录下提供了兼容 RuoYi-Vue 的前端页面，目录结构如下：

```

│   ├── api
│   │   ├── medical
│   │   │   ├── patient.js      # 患者管理 API
│   │   │   ├── diagnosis.js    # 诊疗管理 API（含费用汇总 getFeeSummary）
│   │   │   ├── drug.js         # 药品管理 API
│   │   │   ├── statistics.js   # 数据看板 API
│   │   │   └── followup.js     # 患者随访 API【新增】
│   │   └── monitor
│   │       └── job.js          # 定时任务 + 日志 API【新增】
│   └── views
│       ├── medical
│       │   ├── patient
│       │   │   └── index.vue   # 患者管理页面（内置"随访记录"弹窗）【更新】
│       │   ├── diagnosis
│       │   │   └── index.vue   # 诊疗管理页面
│       │   ├── drug
│       │   │   └── index.vue   # 药品管理页面
│       │   ├── statistics
│       │   │   └── index.vue   # 医疗数据看板页面
│       │   ├── feeReport
│       │   │   └── index.vue   # 费用明细报表页面【新增】
│       │   └── followup
│       │       └── index.vue   # 患者随访管理页面【新增】
│       └── monitor
│           └── job
│               ├── index.vue   # 定时任务管理页面【新增】
│               └── log.vue     # 定时任务日志页面【新增】
```

### 3.2 将页面集成到 RuoYi-Vue

1. 将 `ruoyi-ui/src/api/medical` 复制到 RuoYi-Vue 项目的 `src/api/` 目录下。
2. 将 `ruoyi-ui/src/views/medical` 复制到 RuoYi-Vue 项目的 `src/views/` 目录下。
3. 在 RuoYi-Vue 项目的 `src/store/modules/permission.js` 中确保动态路由已开启（若依默认已开启）。
4. 执行 `sql/medical_menu.sql` 将菜单权限数据导入到若依的 `sys_menu` 表中。

### 3.3 启动前端

```bash
cd ruoyi-ui  # 或你本地的 RuoYi-Vue 项目根目录
npm install
npm run dev
```

> 注意：若 `ruoyi-ui` 目录下缺少 `package.json`（部分源码仓库仅提交 `src`），请先补齐 RuoYi-Vue 前端依赖清单（Vue 2 + Element-UI + axios + js-cookie，echarts 可选）再执行 `npm install`；或将 `src/api/medical` 与 `src/views/medical` 直接复制到一份完整的 RuoYi-Vue 工程中集成。

启动成功后访问：`http://localhost:80`（具体端口以若依前端配置为准）。

## 四、代码生成器使用说明

### 4.1 生成器入口

后端代码生成器模块为 `ruoyi-generator`，访问路径：

- 查询已导入表：`GET /tool/gen/list`
- 导入数据库表：`POST /tool/gen/importTable?tables=medical_patient,medical_diagnosis,medical_drug`
- 预览代码：`GET /tool/gen/preview/{tableId}`
- 下载代码：`GET /tool/gen/batchGenCode?tables=medical_patient,medical_diagnosis,medical_drug`

### 4.2 使用流程

1. 确保 `application.yml` 中的 `gen` 配置正确：

```yaml
gen:
  author: ruoyi
  packageName: com.ruoyi.system
  autoRemovePre: false
  tablePrefix: sys_
```

2. 调用导入接口将数据库表导入到代码生成器：

```bash
curl -X POST "http://localhost:8080/tool/gen/importTable?tables=medical_patient,medical_diagnosis,medical_drug"
```

3. 调用下载接口生成并下载前后端代码压缩包：

```bash
curl -X GET "http://localhost:8080/tool/gen/batchGenCode?tables=medical_patient,medical_diagnosis,medical_drug" -o ruoyi_gen.zip
```

4. 解压后将生成的代码按需放到对应模块中即可。

## 六、常见问题

### 6.1 编译时提示依赖缺失

请确保 Maven 已正确安装，并且网络可访问 Maven 中央仓库。首次编译会自动下载依赖。

### 6.2 MyBatis Mapper 绑定失败

检查 `application.yml` 中 `mybatis.mapper-locations` 配置是否为 `classpath:mapper/**/*.xml`。

### 6.3 前端页面无法显示

确认 `sql/medical_menu.sql` 已执行，且 RuoYi-Vue 的权限缓存已刷新（重新登录即可）。

### 6.4 导出 Excel 为空

导出接口不会进行分页，会导出全部查询结果。请确保查询条件正确，并且实体类字段上已添加 `@Excel` 注解。
